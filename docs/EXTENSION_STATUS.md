## HWP 인쇄 레이아웃 상속 수정 (진행 중)

사용자가 HWP 모아찍기 설정이 PDF에 그대로 반영되는 문제를 보고했다. hwp_pdf.export_pdf에서 한컴 공식 회피 방법인 PrintToPDFEx를 사용하고 PrintMethod=0, Range=0, NumCopy=1, ReverseOrder=0, UserOrder=0을 명시하도록 변경했다. 물리 프린터로 잘못 출력하지 않도록 Hancom PDF가 등록된 경우에만 실행하며, 결과 PDF 페이지 수를 HWP PageCount와 대조한다. 이 방식의 비규격 용지 크기 보존은 추가 확인이 필요하다.

기존 인쇄 방식 0~10을 초기화하는 단위 검사, PDF 드라이버 미설치 시 거부와 LibreOffice 검사 총 14개 통과. 실제 HWP/HWPX 4페이지 모아찍기 시험 스크립트를 추가했으나 기존 allow_job의 RegisterModule이 False를 반환해 실제 출력 단계에 도달하지 못했다. 한글 버전은 12.0.0.535이다. 짧은 모듈명, 32/64비트 레지스트리, HwpCtrl 경로, 등록 순서, 직접 경로 등은 해결하지 못했다. 진단 DLL의 DllMain 로드 표시도 생성되지 않았다. 테스트 실행 계정은 일반 sandbox에서는 기존 Hwp와 다르지만 require_escalated에서는 동일함을 확인했다. 현재 이 수정의 실제 한글 출력 성공 및 설치본 적용은 미검증이며 완료로 판단하지 않는다.

공식 근거: https://forum.developer.hancom.com/t/saveas-pdf/1670/2 및 https://forum.developer.hancom.com/t/saveas-pdf/2400/2 . 원본 저장 대신 변환 전용 인스턴스에서 출력하고 원본 파일 보존을 검사하도록 설계했다.

한글 접근 모듈 추가 진단: 문서를 열지 않은 별도 인스턴스에서 한컴 공식 예제 DLL도 등록 실패했다. 자체 DLL만의 문제로 판단할 근거는 없으며, 한글/실행 환경의 모듈 등록 경로 검증이 남아 있다. HPrint 공식 명세에 따라 사용자 지정 인쇄 범위와 자동 인쇄 머리말/꼬리말도 초기화했다. 잘못된 2쪽 출력(원문 4쪽), 인쇄 실행 실패, 기존 파일 보존을 추가해 HWP/LibreOffice 검사 16개 통과. 실제 HWP 출력 성공으로 기록하지 않는다.
