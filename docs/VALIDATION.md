# 정식 배포 검증 기록

아래 결과는 2026-09-12 현재 직접 수행한 검증만 기록한다. 배포 대상은 사용자의 현재 Windows PC와 비공개 저장소다.

## 통과

- `tests/viewer_smoke.py`: 독립 뷰어 렌더링·페이지 이동·150% 확대 및 UI의 중간 페이지 삭제. 3페이지 중 2번 삭제 후 1·3번 유지, 원본 SHA 동일, 전체 삭제 거부.
- Windows 기본 앱 설정에서 어잉PDF 항목 및 `.pdf` 연결 선택을 확인. 현재 사용자 `FileExts/.pdf/UserChoice`의 ProgId가 `EoingPDF.Document`인 것을 확인했다.
- 로그 파일 접근이 거부되는 환경에서도 임시 로그/무로그로 시작하도록 수정. 동일 환경에서 실제 `main.py PDF --screenshot` 뷰어 시작과 정상 종료를 확인했다.

- `python -m unittest discover -s tests -v`: 14개 통과.
  - 페이지 추출 순서/중복, 잘못된 범위와 과도한 숫자, 선택 페이지 회전
  - 이름 충돌 시 기존 출력 보존, 취소 시 임시 파일 정리, 암호 PDF 거부
  - PNG ZIP/텍스트 추출, 페이지 번호, CP949 한글 입력
  - PDF/PNG/TXT 혼합 병합, 여러 프레임 TIFF
  - 요약 출처 페이지, 부분 실패 명시, 모든 테스트의 입력 SHA-256 보존
- `tests/ui_smoke.py`: 편집창 버튼 → 작업 스레드 → 출력, 빠른 병합창 → 2페이지 출력.
- `tests/native_smoke.py word excel powerpoint`: 새로 만든 DOCX/XLSX/PPTX를 실제 Office로 PDF 변환하고 텍스트 및 페이지 확인.
  - 첫 측정은 테스트 문서 생성 시간을 포함하여 Word 9.58초, Excel 5.69초, PowerPoint 3.36초. 변환 단독 성능으로 해석하면 안 된다.
- 포터블 EXE에서 `--screenshot` 정상 종료 및 화면 생성.
- 우클릭 연결 프로그램의 CF_HDROP 자체 검사: 여러 파일과 한글/공백/특수문자 경로 보존.
- COM 서버를 직접 시작한 통합 검사: 전체 선택 전달 → 포터블 앱 빠른 병합 → 실제 2페이지 출력 확인.
- **탐색기 실제 우클릭**: 앱에서 메뉴 등록 후 두 PDF를 선택하여 병합, 2페이지와 본문 순서를 확인했다. 메인 창 없이 빠른 작업창이 자동 실행됐다.
- HWP/HWPX: 실제 사용자 탐색기에서 실행한 검사로 한글 2022 변환 성공. 각각 4.62초/4.52초(테스트 문서 생성 포함). 접근 DLL 해제 시 정리 오류를 수정했다.
- DOC/RTF/XLS/XLSM/PPT/PPTM: 실제 Office 변환 성공 및 입력 SHA-256 보존. 문서 생성 포함 10.69/9.19/7.52/5.64/3.72/0.62초.
- `tests/ocr_smoke.py`: 글자층 없는 한글 스캔 이미지 → Windows OCR → 텍스트 및 페이지 출처를 붙인 발췌 요약 통과.
- 2026-09-12 `tests/hwp_cancel_smoke.py`: 의도적으로 대기하는 도우미로 취소/시간 초과를 재현. 부모 프로세스에서 도우미 종료, 접근 허용 파일과 임시 레지스트리 값 제거, 원본 보존을 확인했다. 실제 한글 COM 무응답 자체를 재현한 검사는 아니다.
- 배포본에 포함된 OCR 실행 파일로 한글 스캔 PNG를 읽어 3문장 인식 성공.
- 2026-09-12 수정본: 탐색기에서 실행한 HWP/HWPX 회귀 검사 성공(문서 생성 포함 4.28/3.89초).
- 최종 EXE: 메인 창을 닫은 상태에서 HWP 우클릭 변환 → 빠른 창 완료 1/실패 0 → PDF 본문 `EoingPDF Hancom conversion test` 확인. 같은 HWP 우클릭 요약 → `sample_요약.txt`에 출처 파일과 `[p.1]` 본문 확인.
- 메뉴 등록/해제/재등록을 배포 앱에서 실행. 이전 메뉴 설정은 `LocalAppData/EoingPDF/backups/legacy-menu-20260912-042942-776364.json`에 백업. 실제 HWP 전체 메뉴에서 새 3개 항목 확인.
- `tests/performance_smoke.py`: 텍스트 PDF 20개·200페이지 병합 엔진 0.115초. 모든 페이지 본문 순서 및 입력 해시 일치. 앱 실행, 스캔, Office 변환이 제외된 합성 입력 측정이며 일반 문서 성능 보장은 아니다.

## 미해결 / 미검증

- 개발 명령 실행 환경의 COM 등록/한글 모듈 등록은 실제 사용자 탐색기 실행과 결과가 달랐다. 실제 탐색기 경로에서는 성공을 확인했으며, 환경 차이의 정확한 원인은 단정하지 않는다.
- 현재 PC와 다른 Windows/Office/한컴 버전의 호환성은 추가 검증 대상이다. Windows 11 기본 축약 메뉴 통합은 후속 범위이며 현재는 더 많은 옵션 표시에서 작동한다.
- GitHub 저장소 삭제/재생성: 2026-09-12 권한 승인 후 완료. 기존 ID 1280267163 → 새 ID 1366623248, 비공개 설정 유지. 이전 이력 번들 검증 완료.
- 빠른 창을 작업 시작 전에 닫는 경우 실행하지 않도록 수정하고 UI 검사 통과. 병합 단계 취소도 실패 없이 취소 상태를 반환하도록 수정하고 회귀 검사 통과.

## 수정된 배포 문제

PyInstaller가 PATH의 제3자 `icuuc.dll`을 수집하여 QtCore 로딩에 실패했다.
Windows 10/11 기본 ICU를 사용하도록 패키징에서 잘못된 ICU를 제외했으며, 배포 EXE 실행으로 수정 확인했다.
실사용하지 않는 Qt 플러그인을 제외한 중간 빌드는 ZIP 약 52MiB다. 최종 해시/크기는 마지막 빌드 후 다시 기록한다.
