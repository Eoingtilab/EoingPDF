# 어잉PDF 2 개발 방향과 구현 방안

## 최우선 사용자 흐름

탐색기에서 문서 선택 → 우클릭 → PDF 변환 / 합치기 / 핵심문장 요약 → 같은 폴더의 새 결과 파일.
메인 앱을 먼저 열거나 파일을 다시 고르는 과정은 없앤다. 실행 중에만 작은 진행창을 표시한다.
메인 창은 페이지 정리, 회전, 미리보기 등 추가 작업용이다. Pretendard를 번들로 제공한다.

## 구현 구조

- `main.py`: 명령행 분기. 빠른 작업은 전체 편집창을 만들지 않는다.
- `shell.py`: 현재 사용자 우클릭 메뉴와 COM DropTarget 등록/해제. 관리자 권한과 상주 프로세스 불필요.
- `quick.py`: 탐색기에서 들어온 파일을 모아 작은 진행창에서 자동 처리. 중단과 결과 폴더 열기.
- `convert.py`: 이미지/텍스트 자체 변환, Office/한글 별도 프로세스 변환. 제한 시간과 읽기 전용 처리.
- `core.py`: 병합, 선택 페이지 추출/순서 변경, 회전, 무손실 최적화, 이미지/텍스트 추출, 페이지 번호.
- `summary.py`: 외부 전송 없는 빈도 기반 핵심문장 추출. 출처 문서와 페이지 표시. 생성형 AI와 명확히 구분.
- `app.py`: 전체 도구 화면. 처리 엔진과 분리한다.

## 형식별 전략

| 입력 | PDF 변환 | 전제 / 제한 |
|---|---|---|
| PDF | 그대로 합치기/최적화 | 암호 PDF는 해제한 사본 필요 |
| JPG, PNG, WEBP, BMP, TIFF | 자체 엔진 | 페이지 수와 원본 보존 검사 |
| TXT, CSV, MD | 자체 텍스트 PDF | UTF-8/UTF-16/CP949, CSV는 원문 표기 |
| DOC, DOCX, RTF | Word PDF 출력 | Microsoft Word 설치 필요 |
| XLS, XLSX, XLSM | Excel PDF 출력 | Excel 설치, 매크로/링크 업데이트 차단 |
| PPT, PPTX, PPTM | PowerPoint PDF 출력 | PowerPoint 설치, 열려 있는 사용자 앱 강제 종료 금지 |
| HWP, HWPX | 한글 PDF 출력 | 한컴 한글 설치, 보안 확인창이 나타날 수 있음 |

Windows에서 열리는 모든 파일이 자동 변환 가능한 것은 아니다. 지원 확장자와 렌더러를 명시한다.
Office/HWP 문서는 원래 레이아웃을 보존하는 네이티브 출력만 사용한다. 텍스트만 뽑은 결과를 원본 변환으로 위장하지 않는다.
스캔 문서는 Windows 내장 OCR을 사용한다. 생성형 AI 요약은 후속 확장 대상이며 현재 빠른 요약은 추출식이다.

## 속도와 안정성

1. Qt와 PDF 엔진만 기본 로드. Office 자동화는 해당 형식을 처리할 때만 별도 프로세스에서 로드.
2. 포터블 폴더 배포로 실행마다 압축을 푸는 단일 EXE의 지연을 피한다.
3. 매크로 비활성화, 외부 링크 업데이트 차단, 원본 읽기 전용. 자체 파일만 정리한다.
4. 결과는 새 파일. 이름 충돌 시 번호를 붙인다. 실패하면 불완전한 출력 제거.
5. 문서별 성공/실패를 표시하고 병합은 누락을 숨기지 않는다.
6. 변환 프로세스 시간 제한, 중단 지원. 사용자가 열어 둔 Office 프로세스를 일괄 종료하지 않는다.
7. 여러 선택 파일은 COM DropTarget의 CF_HDROP 목록으로 한 번에 전달한다. Windows 11에서는 더 많은 옵션 표시에서 실행하며 실제 탐색기 병합을 검증했다.

## 검증과 완료 기준

- PDF/이미지/텍스트 혼합 병합과 변환, 한글 텍스트, 추출식 요약 출처 확인.
- Office와 HWP는 설치된 앱으로 실제 예제를 변환 후 페이지 수/텍스트 확인.
- 이름 충돌, 잘못된 페이지, 손상/암호 파일, 중단, 원본 SHA-256 동일성 검사.
- 우클릭 등록/해제와 여러 파일 전달, 빠른 창 동작, EXE 실행 확인.
- 빈 화면/파일 화면을 캡처하여 Pretendard, 잘림, 버튼 활성화 점검.
- 검증 불가능한 형식은 문서에 표시하고 완료 주장하지 않는다.
