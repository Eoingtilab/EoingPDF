# 기능 점검 및 자동 양식 수정 기록

점검일: 2026-10-08 (한국 시간). 아래 기록은 Microsoft Store 준비 브랜치에서 수행한 최초 소스 점검 당시의 결과다. 그날은 기존 2.2.2 설치파일과 공개 배포물을 변경하지 않았다.

2026-10-09의 2.2.3 정식 배포는 `origin/main`에서 별도 작업 폴더를 만들고 자동 양식 수정만 반영했다. Store 준비 기능과 관련 번역 보완은 정식 배포에 포함하지 않는다. 설치형·포터블 실행파일의 양식 생성 및 한글 저장을 빌드 필수 검사로 추가했다. 현재 배포 범위는 `docs/RELEASE_NOTES.md`를 참조한다. 아래의 '미배포'·'소스에만 반영' 표현은 최초 점검 당시 상태를 뜻한다.

## 결론

모든 개발 기능이 모든 실제 문서와 환경에서 정상이라고 판단할 근거는 없다. 기존 자동 검사에서 누락했던 **Word 표 PDF의 입력 칸 자동 생성 오류**를 실제 Office 출력으로 재현하고 수정했다. 아래 검사는 현재 소스에 대한 결과이며 설치된 앱의 동작을 보증하는 결과가 아니다.

## 확인한 문제와 수정

1. **공유 테두리 표:** 기존 감지는 독립 사각형과 수평선 위주라 오른쪽 빈 셀 3개를 놓치고 행 전체를 가로지르는 칸 2개를 만들었다. 표 선의 교차점에서 실제 셀을 찾고 글자가 있는 셀과 기존 필드는 제외하도록 수정했다.
2. **실제 Word PDF 테두리:** Word에서 새로 만든 3행 2열 표를 PDF로 내보내면 테두리가 약 0.48pt 두께의 검정 채움 도형으로 저장됐다. 기존 코드가 유색 채움 도형을 제외해서 빈 칸을 하나도 찾지 못했다. 얇은 채움 도형을 선으로 취급하고 굵은 채움 블록은 계속 제외한다. 수정 후 오른쪽 빈 셀 3개를 정확히 생성했다.
3. **네 선 박스·병합 셀:** 사각형 명령이 아닌 네 선으로 그린 박스와 병합된 빈 셀도 감지한다. 높은 텍스트 칸은 여러 줄 입력 필드를 사용한다.
4. **행 구분선 오감지:** 감지한 셀의 경계와 겹치는 수평선을 별도의 밑줄 입력 칸으로 생성하지 않는다.
5. **새 감지 경로의 작업 프로세스 통신:** 표 감지 라이브러리의 안내 출력이 JSON 진행·완료 메시지와 섞이면 앱이 저장 프로세스를 중단했다. 일반 출력과 라이브러리 안내를 stderr로 보내고 stdout에는 진행·완료 메시지만 보내도록 수정했다. 독립 프로세스의 출력 검사를 추가했다.
6. **기존 검사 실패:** 전체 기존 검사에서 실패했던 번역 검사 2개는 한국어 Microsoft Store 안내 5개의 리소스 누락이 원인이었다. 다른 두 언어와 키를 맞췄다.

새 자동 검사는 공유 테두리의 일반 선/채움 선 각각에서 0/90/180/270도 회전과 CropBox를 검사한다. 기존 필드 중복 방지, 채워진 셀 제외, 원본 보존, 한글 저장, 새 프로세스의 출력 형식도 포함한다.

얇은 채움 선 보완 후 채움 선 회귀 검사와 실제 Word 출력 검사를 수행하고, 최종 소스로 전체 자동 검사 및 Windows 화면 검사를 모두 실행했다.

## 변경 파일

- `src/eoingpdf/forms.py`: 표 셀·얇은 채움 선·네 선 박스 감지, 행 구분선 제외, 높은 텍스트 칸의 여러 줄 입력.
- `src/eoingpdf/transform_process.py`: 저장 프로세스의 일반 안내 출력과 JSON 통신 분리.
- `assets/locales/ko-KR.json`: 기존 Microsoft Store 안내 5개 추가.
- `tests/test_forms.py`: 공유·채움 테두리, 회전·CropBox, 네 선 박스·병합 셀, 채움 밑줄 회귀 검사.
- `tests/test_form_review.py`: 표 감지 검토 → 한글 입력 → 새 PDF 저장 흐름과 화면·PDF 렌더링 자료.
- `tests/test_processes.py`: 표 감지 자식 프로세스의 JSON 출력 검사.
- `README.md`: 표 양식 감지 범위·제약과 이미 지원하는 선택 목록·라디오 입력 설명 갱신.
- `CHANGELOG.md`, `ROADMAP.md`, 이 문서: 소스 수정, 검사 결과, 미배포 상태 기록.

실제 Word 검사용 스크립트는 `temp/verify-word-table-forms-20261008.py`에 두었다. 새 시험 문서만 만들며 사용자 문서를 열지 않는다. `temp/`의 자료는 Git 배포 소스에 포함되지 않는다.

## 남은 범위

- 사용자가 문제가 있다고 한 원본 PDF는 제공되지 않아 해당 파일 자체는 검증하지 않았다. 실제 Word에서 만든 새 표로 같은 종류의 실패를 확인했다. 실제 한글 프로그램의 다양한 표 출력은 이번에 별도 검사하지 않았다.
- 스캔·촬영 이미지와 테두리 없는 표는 자동 감지하지 않는다. 글자가 이미 들어 있는 셀 전체에 자동 입력 칸을 덮지 않으므로 같은 셀에 제목과 답란이 섞인 서식은 누락될 수 있다.
- 외부 PDF 뷰어별 한글 재편집·양식 호환성, 모든 실문서의 자동 감지율, 물리 프린터·펜·다중 모니터, 실제 설치·업데이트 서버의 전 과정은 이번 점검으로 보장하지 않는다. 자동 검사의 모의 입력·합성 문서를 실제 장비·문서 검사와 구분해야 한다.
- 수정은 소스에만 반영했다. 기존 `release/`의 설치·포터블 EXE와 사용자 PC의 설치본에는 적용되지 않는다. 배포하려면 새 패키지를 빌드하고 수정본 실행파일에서 표 양식 생성을 확인해야 한다.

## 다시 검사하기

```powershell
.venv_d/Scripts/python.exe -m pytest tests -q --tb=short --junitxml=temp/test-results/forms-audit-20261008.xml
.venv_d/Scripts/python.exe temp/verify-word-table-forms-20261008.py
```

Word 시험에는 설치된 Microsoft Word가 필요하다. 프로그램은 보이지 않는 별도 인스턴스에서 새 시험 문서를 만들고 완료 후 닫는다.
